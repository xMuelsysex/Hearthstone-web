# 战场拖拽、镜像布局与简化卡面

## 目标与决策

- 让抓取中的卡牌以鼠标指针为锚点实时跟随，移除移动端把拖拽预览固定到左上角的规则。
- 让对手区域形成玩家区域的水平镜像：对手手牌在上、对手英雄在中、对手战场靠近中线；玩家战场靠近中线、玩家英雄在中、玩家手牌在下。
- 已放置在战场的卡牌只展示原画裁切与实时攻击/生命；手牌、Discover、inspection、拖拽预览继续使用完整卡面。
- 右侧牌库上下竖向排列，对手牌库在上、我方牌库在下；保留公开数量、has-cards/empty 和悬停/聚焦交互。

## 计划

1. 读取合并后 root 的拖拽、英雄、战场卡牌、牌库实现与既有测试契约。
2. 以最小 diff 修改 `GameBoard.tsx` 和 `theme.css`，保留公开投影、命令派发、可访问性和现有拖放目标。
3. 同步组件/E2E 几何契约，覆盖指针跟随、水平镜像、战场裁切和牌库排列。
4. 依次运行目标 Vitest、typecheck、lint、architecture、build 及 M1/M3/M4 真实浏览器检查，记录结果并复核工作区范围。

## 验证记录

- 目标 Vitest：`pnpm exec vitest run src/ui/game/GameBoard.test.tsx src/ui/card/CardPreview.test.tsx src/app/App.test.tsx`，3 files / 17 tests 通过。
- 静态门禁：`typecheck`、`lint`、`test:architecture` 三项 enforcement、`build` 全部通过；生产构建 140 modules。
- 真实 Chromium：M1 `e2e/m1.spec.ts` 11/11 通过；M3/M4 定向门禁 2/2 通过。
- 浏览器验收：1280×720、1920×1080 页面滚动尺寸等于视口；390px 无横向溢出。对手区域顺序为手牌 → 英雄 → 战场，玩家区域顺序为战场 → 英雄 → 手牌；右侧牌库为对手在上、我方在下。战场卡牌 DOM 具备原画裁切和攻击/生命数据，费用层不存在。
- 拖拽验收：真实鼠标拖拽中预览卡面中心与起点/终点指针误差约 1px；控制台 errors=0。`git diff --check` 通过。

## 结论

- `GameBoard.tsx` 用指针坐标驱动拖拽预览，移除移动端固定浮空位置；对手英雄调整到对手手牌与战场之间，形成玩家区域的水平镜像；战场随从统一使用原画裁切 + 动态攻击/生命宝石。
- `theme.css` 将两方牌库改为右侧纵向对应排列，并同步桌面、低高度桌面与 390px 响应式布局。
- 测试契约覆盖拖拽跟手、镜像顺序、战场简化卡面与牌库顺序。
